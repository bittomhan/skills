# 投标项目深度评估报告工作流（bid-evaluation-report）

从一条招标公告到一个可供俞总审阅与高管接力推进的完整评估报告。全流程 7 步，其中第 5 步（两轮审查）**不可跳过、不可合并**。

## 适用判断

- 触发词：「调研这个标」「出评估报告」「这个项目能不能投」「给俞总的报告」
- 输入：至少一条已核验的招标/采购公告（通常来自招投标台账）
- 输出：底稿 md（含审计痕迹）→（汇报版）md → 同名 PDF。**PDF 触发条件（08-31 Tom 术语约定）**：Tom 说「生成 PDF」**或「生成汇报版 / 汇报版本 / 出汇报版」**均视为要求出 PDF——说「汇报版」就是要成品 PDF，**不要在生成（汇报版）.md 后就停手交付**，那只是中间文档。全部落位见下方「档案规则」

## 交付物红线：只交完整评估报告，不交「评估思路」（2026-08-24 Tom 定，永久）

**深度调研一旦启动，唯一交付物就是完整评估报告**（S1-S5 全流程走完）。禁止产出「前期调研与评估思路」「投标调研评估思路」这类中间文档当成交付物——Tom 原话：「我需要的是完整的评估报告，你给出的只是评估思路……相当于还得找人重新评估」。历史教训：凤城/宽甸/中烟三标先各写了一份「思路」，结果全部要按鲁山模板重写成完整报告，双倍工作量。

- 「怎么做调研」的框架思考是内部过程，不落成项目夹里的正式交付文档；确需留底进 `竞争情报/` 或工作笔记
- 若项目夹里已有旧的「评估思路」文档：升级为完整评估报告后，把旧思路文档移入 `归档/`（失效留痕），项目夹交付层保持「评估报告三件套」干净结构
- 报告深度对标 source_case 鲁山样例：十二个章节、历史中标脉络表、竞争格局画像、政策硬约束逐条引用文号、能力缺口逐系统拆解、成本测算框架、条件式 Go/No-Go + 三选项战略定位表

**适用分支**：
- **A. 单标评估**（默认）：一条公告 → 一份报告，投不投这个标。
- **B. 赛道级评估**（2026-08-31 新增）：当同一采购人体系**短期内连续释放多个同类标**（如新疆农商行 40 天内巴州/伊犁/塔城三个中心支行连续挂网），或 Tom 问的是「这个方向/这条赛道能不能做」时，**不要按单标写**——按赛道写：①把已释放的标列成一张表（发布/截止/内容/入围/状态）；②论证采购范式是什么、是否会持续复制；③用**我方在该范式下的已中标案例**作为「能做」的核心证据；④给出下一年度窗口的布局路径而非单标倒排。首例：`01_可参与在途/260831新疆农商行监管外包赛道/`。

## 档案规则：扁平目录 + 调研研究分离（2026-08-24 Tom 定；2026-08-25 扁平化改版）

**目录骨架**（`招投标简报/` 下，⚠️ 08-25 起**已扁平化**，无 `项目/` 中间层、无 `源文档/` 层）：

```
招投标简报/
├── 2026-MM招投标台账.md          ← 活文档恒在根目录，唯一索引
├── 01_可参与在途/                 ← 【在途】截止 > 今天的项目夹
│   └── <YYMMDD><项目短名>/        ← 本 skill 全部产出落这里
│       ├── YYMMDD<项目短名>评估报告.md          （底稿，恒保留）
│       ├── YYMMDD<项目短名>评估报告（汇报版）.md （中间文档；PDF 成功后删除）
│       └── YYMMDD<项目短名>评估报告.pdf         （仅 Tom 要求时）
├── 02_已截止归档/                 ← 截止 ≤ 今天的项目夹（规则见 bid-folder-placement-maintenance）
├── 公告存档/                      ← 官方公告原文，根目录一级
├── 竞争情报/                      ← 竞对画像、历史中标数据等通用件
└── 归档/                          ← 失效留痕（根目录下一级，视情况用）
```

**五条硬规则**：
1. **建夹时机**：深度调研一旦启动即建夹（评估报告天然三件套，无需等第 3 份文档）。**夹名 `YYMMDD` = 项目递交截止/开标日期**（不是发现日）；截止时间未核实的暂存条目保留原命名。截止 > 今天进 `01_可参与在途/`，≤ 今天进 `02_已截止归档/`，每轮台账维护后按 `bid-folder-placement-maintenance` skill 核对归位。
2. **调研/研究判据**：「删掉这份文档，结论是否失去依据」——失去依据=调研，进 `公告存档/` 或 `竞争情报/`；本身就是结论=研究，进项目夹。外圈调研（第二步）的中间产物不堆在项目夹里。
3. **命名分工**：研究层文件带日期前缀 `YYMMDD名称`（跟交付走）；调研层通用材料主题命名不带日期（如 `内蒙古农商行动态名单机制.md`），日期放文档头部。例外：`公告存档/` 内 per-bid 证据用 `YYMMDD<项目短名>-公告原文` 命名。
4. **公告必须存档**：第一步官方核验完成后立即存 `公告存档/`——聚合站链接会失效，这是台账可审计性的底线。
5. **赛道级报告例外**：覆盖多个标、无单一截止日期时，夹名可用**报告产出日**（如 `260831新疆农商行监管外包赛道`），但须在台账注明「赛道级评估夹，非单标夹」；其中仍在途的单标档案保留其独立夹。

## 第零步：定位声明

动笔前先锁定三件事，防止返工：
1. **受众**：俞总+高管团队（结论前置但保留完整论证，不做一页纸摘要）
2. **决策问题**：投不投？以什么定位投？（可参与 / 战略卡位 / 仅对标）
3. **硬约束**：Tom 的指令性边界（如鲁山案例中「国内科技线不碰 RWA」「不要决策摘要要完整考量」）

## 第一步：公告要素核验（S1）

- 从**官方渠道**（政府采购网、交易平台原文页）逐项核对：项目编号、采购人/组织方及联系方式、采购方式、预算/限价、数量与入围规则、保证金、平台费、CA 要求、文件获取窗口、响应截止/开标时间、开标方式（远程/现场）、联合体政策。
- ⚠️ **聚合站（千里马/剑鱼/globaltenders 等）信息只作线索**：曾出现聚合站截止时间错误 8 天的情况（globaltenders 把 09-03 报成 09-05）。凡聚合站数据必须回官方原文验证后才可写入报告。
- 用 WebFetch 抓详情页而非只看搜索摘要。
- ✅ 核验完成即存档：公告原文快照/PDF 落 `公告存档/YYMMDD<项目短名>-公告原文.md`（根目录一级，见「档案规则」第 4 条），再进入后续步骤。

## 第二步：外圈调研（S2）——公告之外的四层情报

公告本身只有骨架，评估价值在外圈。四层依次检索：

| 层 | 内容 | 典型信源 |
|---|---|---|
| L1 采购人背景 | 银行/机构的体量、改革沿革、战略方向、同类采购的历史规律（判断「一次性 vs 常态化」） | 官网、财经媒体、金融监管局新闻 |
| L2 本地场景 | 项目所在地的产业结构=未来押品品类结构；**⭐园区/采购人的招商合作方向（09-02 德州发现：「轨道 B」——园区招商若明确欢迎监管仓/监管服务类企业，则存在不依赖投标结果的业务合作路径，与轨道 A（投标）并行论证）** | 海关数据、地方政府公开文件（政协提案答复是好信源）、统计公报、**园区招商公开材料/招商公众号** |
| L3 竞争格局 | 每个竞对/白名单成员的注册地、业务品类、扩张动向（招聘信息是金矿——能看出对手正在哪里抢市场）、资质背书（是否参与国标起草等） | 企业官网、招聘网站/公众号招聘帖、国标起草单位名录 |
| L4 自身档案 | 我方与该采购人的历史交集、白名单/入围状态、品类匹配度、地理半径缺口、**我方在同类采购范式下的已中标战绩** | 见下方「L4 强制动作」 |

### ⭐ L4 强制动作：反查我方公开中标战绩（2026-08-31 增补，血泪教训）

**写「我方匹配度与缺口 / 能否做」之前，必须先查我方在该采购范式下的历史战绩——不是靠内部 memory 回忆，而是用公开商业数据库反查。**

标准检索式（逐条跑，不要合并）：

```
"宁夏嘉宝信仓储服务有限公司" 中标
"嘉宝信" + <本项目所在地区名，如 塔城 / 新疆 / 乌海>
"嘉宝信" + <本次采购品类，如 第三方监管 / 动产质押 / 活体>
```

信源优先级：**招标网/中国招标投标公共服务平台的公示正文**（会列出全部中标人姓名）> **爱企查 / 企查查 / 天眼查的「招投标」标签页**（三者数据不一致很常见，需交叉）。

**三条使用纪律**：
1. **口径分歧必须标注，不能二选一写死**。天眼查归「中标结果」、企查查标「投标方」时，正文中写「出现在中标结果公示中（天眼查归中标结果/企查查标投标方，口径不一，待内部核实合同）」，不要直接写成「已中标」。
2. **找到的最强证据要单独成节论证其意义**，不能只躺在战绩表里。示例：找到「内蒙古农商银行乌海中心支行集中采购动产押品监管服务（2026-05-07，5 家入围之一）」，就要点明「本次新疆农商行中心支行监管项目是同一采购范式的复制，这不是能不能做的推测，是已经做过的事实」。
3. **改变结论的新证据必须在报告里显式标明「改变了此前判断」**，并同步回写台账条目——否则旧报告的结论会继续误导决策。

> ⚠️ **教训来源**：塔城中心支行第三方监管评估报告（08-31 首版）在 L4 只写了「T3 区外、无现成网点、需新建驻点、启动成本 5-15 万」。补做反查后发现：①嘉宝信 2026-05 已中标内蒙古农商行乌海中心支行同类项目；②嘉宝信 2025-09 已出现在农行塔城兵团分行「农易购」中标结果公示中——第二条若确认，塔城项目直接从「从零起步」变成「在自家地盘加一层」，成本侧结论整个反转。**漏掉这一步 = 用错误的成本假设做 Go/No-Go 决策。**

另做**商业测算**：限价分档表 → 收入空间（注意入围家数摊薄）→ 费率行情纵向对比（用我方历史案例费率 vs 本次限价，量化行业价格战幅度）→ 成本变量（驻场人力行情价可从竞对招聘帖直接取得）→ 给出定价带建议。

⚠️ **自身体量约束要诚实写进报告**：若从工商数据看到我方员工人数/营收规模与项目体量不匹配（如「13 人 / 年营收 1000 万」要去承接「14 个中心支行」的跨省铺开），必须在约束章节明写——交付能力是硬约束，中标能力解决不了。

⚠️ 落位纪律：本步产出的中间调研材料（采购人背景、竞对画像底料、政策摘录、历史中标数据）落 `招投标简报/竞争情报/`（根目录一级），**主题命名不带日期**；项目夹内只放结论性文档——不要把调研过程文件堆进项目夹。

## 第三步：底稿撰写（S3）

参照模板结构（见 source_case 两份样例）：

```
# <项目名> — 投标评估报告
> 分析时间: YYYY-MM-DD | 分析人: 韩悠阳
> 信息来源：<逐项列出>
一、项目概况与决策窗口（基本信息表 + 决策时间线，物理门槛标⚠️）
二、采购人背景
三、竞争格局（画像表 + 格局判断）
四、商业测算
五、我方匹配度与缺口（✅优势 / ⚠️缺口 分列）
六、风险清单（表格：风险|等级|缓释措施）
七、结论与行动建议（Go/No-Go 条件式结论 + 倒排表）
八、待内部确认/待核实信息清单
```

⚠️ 头部信息行红线（2026-08-24 Tom 定）：**不写「报告性质」行**；分析人一律署「**韩悠阳**」，不用 Tom / Tom Han。

写作红线：
- 每个关键事实标置信度 **[高]/[中]/[低]**；推断结论必须写明「推断」，不得伪装成事实
- 数字标注口径与时点（关区≠城市、预算价≠成交价、统计期间非自然年等）
- 单源未交叉验证的数据标 ⚠️单源
- 地理距离/换算类数字标 [低/地图级估算]
- 结论必须是**条件式 Go/No-Go**：列出成立前提，不拍脑袋
- 输出位置：`招投标简报/01_可参与在途/<YYMMDD><项目短名>/`（截止 ≤ 今天则 `02_已截止归档/`），命名 `YYMMDD<项目短名>评估报告.md`（见「档案规则」）

## 第四步：两轮审查（S4）——不可跳过

写完后立即执行，不允许「先交付后补审」：

**R1 通读逐条核查**：对照信源逐一核对每个事实性陈述（编号、金额、日期、名称、名单成员数）。重点抓：
- 信源张冠李戴（如把 A 文件的接口清单归到 B 办法名下）
- 因果单侧归因（重新招标未必=前任做砸，可能有覆盖扩展等其他解释）

**R2 易错点专项复核**：
- 地理距离/里程类数字（曾把呼市—满洲里写成 700 公里，实际 2000+）
- 法规条款归属与期限计算（质疑期=公告期满后 7 个工作日，不是公告期本身）
- 费率/比例的数学一致性
- **行文残留**：套用旧模板时留下的旧项目字眼（曾残留鲁山报告的「16 天倒排」）

**修正落地**：所有修正在底稿顶部加「修正记录（MM-DD 审查）」引用块，格式 `[高/中/低] §章节 问题 → 已改`。底稿保留全部审计痕迹；审查记录**不进**汇报版。

## 第五步：汇报版与交付（S5）

1. 复制底稿为 `<原名>（汇报版）.md`，执行剥离：
   - 删顶部修正记录块
   - 删「待内部确认」中含敏感渠道信息的条目（视受众取舍）
   - 删脚注「本报告为底稿版本…」类写作者自用说明
   - ✅/⚠️/❌ 状态标注属信息内容，保留
2. Tom 说「生成 PDF」**或「生成汇报版 / 汇报版本」**时才转 PDF（08-31 术语约定）：用 md-to-pdf skill（Noto Sans CJK SC），最终 PDF 用原名、不带任何后缀
3. **PDF 生成成功并核验后，立即删除 `（汇报版）.md`**（2026-08-31 Tom 确认，永久）——项目夹交付层只留「底稿 md + 同名 PDF」。PDF 未生成成功则不删（汇报版是唯一可读副本）
4. 同步更新招投标台账该条目的状态备注（已立项调研/Go/No-Go）

## 常见坑（历史教训）

| 坑 | 案例 |
|---|---|
| 聚合站截止时间错误直接采用 | globaltenders 将满洲里项目截止报错 |
| 距离类数字凭感觉写 | 呼市—满洲里误写 700km |
| 模板复用的行文残留 | 「16 天倒排」带入 10 天窗口的新报告 |
| 推断不标注被当成事实 | 白名单区域限定条款的解读必须标「推断，待采购文件确认」 |
| 只算收入不算战略期权 | 名单卡位型项目的价值在可复制路径，须单独论证但不得用它掩盖账面亏损 |
| 调研过程文件混进项目夹 | 外圈调研中间产物一律进 `竞争情报/`（主题命名），项目夹只放结论链——否则一标多文档后无法区分证据与结论 |
