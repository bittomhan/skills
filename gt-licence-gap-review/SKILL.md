# GT 牌照申请缺口审查

两条线：**MPI**（GEMTRUST STABLE，稳定币发行，PS Act / PSN02 / SCS 框架）与 **CMS**（GEMTRUST CAPITAL，资本市场服务，SFA / SFA 04-G01 / AMLOM）。法源不得混用。

## 目录架构

| 角色 | 路径 | 说明 |

### 第 0.5 步：🔴 签名核验标准方法（凡涉及"是否已签署"的判断，必做）

**永久规则：PDF 有【图像 / 文字 / 矢量 Path】三层，签名可能落在任意一层。只看一层 = 必然漏签。**

**本项目已观察到的两种签名形态（Tom 09-02 指出「Li Hua 喜欢这种签名方式」）**：

| 签署人 | 签名形态 | 检出方式 | 实测位置 |
|---|---|---|---|
| **MA Qing** | 手写 → 扫描 → **位图** | `page.get_images()` | CI p1 `(87,659,184,706)`；SL p1 `(85,594,172,637)`；BR **p2** `(81,325,168,366)` |
| **LI Hua** | 电子签名板 → **矢量填充路径** | `page.get_drawings()` 中 `type='f'` | CI p1 `(353,643,451,700)`；SL p1 `(341,578,437,635)`；BR **p2** `(342,312,437,368)` |

**一键核验脚本**（已落 `scripts/10_verify_signatures.py`）：
```bash
PY=/Users/bittom/.workbuddy/binaries/python/envs/default/bin/python3
D=~/.workbuddy/skills/gt-licence-gap-review/scripts
$PY $D/10_verify_signatures.py <pdf1> [<pdf2> ...]
```
输出每份 PDF 的**位图签名数 / 矢量签名数 / Date 文字行**与总判定（≥2 = 双签齐全）。

**脚本的过滤逻辑（v1.2，已实测精准识别本项目的两种签名）**：
- 默认**全页扫描**（不固定 y 范围——BR 的签名在 y≈312 页中，固定页尾范围会漏检）；
- 位图层：过滤宽或高超过页面 90% 的整页背景图；
- 矢量层：仅取 `type='f'`（填充），并过滤 ①面积 <200pt² ②高度 <20pt ③宽高比 >40（横向分隔线）④**宽度 > 页宽 60%**（通栏装饰条/页眉色块——实测真签名宽≈98pt，页眉装饰宽≈459pt）⑤面积 >150,000pt²。

**⚠️ 09-02 血泪教训**：核验 S4-01 三份函件时只查 `get_images()` → 报告「LI Hua 未签、需补签」，并据此写进 MEMORY / skill / 清单 / 审查报告 / 口头汇报——**全错**。实际 LI Hua 已签（矢量 Path）。**教训：凡"是否已签"的判断，必须用 `10_verify_signatures.py` 跑一遍，禁止手工只看 images。**

**两树合并规则**（Tom 09-01 定）：以**更完整的那侧为基底**，把另一侧的独有内容补进去；合并结果**同时写入两树**并用 `cmp` 校验逐字节一致。
- 判断"更完整"不能只看字数——先跑 `06_unique_blocks.py` 双向看独有块。字数长的一侧可能缺另一侧的实质章节（历史教训：MPI TRM 源树更长，但缺递交树的多签/时间锁/HSM、CertiK 鉴证、IT 风险登记册）。

10. **bash `grep` 对含全角竖线「｜」的文件名会静默失败**——返回空、不报错、Exit 0，看起来像「没有匹配」。
    本项目绝大多数文件名都含「｜」（缺口清单、政策文件、任命书全部如此），所以用 bash grep 检索等于**系统性漏检**。
    **09-01 实例**：据此误判「MPI 保证金是新发现的漏项」，实际 08-20 已以 `MPI-IPA-07` 记录；同轮又误判 CMS 侧 reg 7 押金为新发现，实际 09-01 上轮已记为 `CMS-S4-06`。两次误报。**凡检索一律用 Grep 工具（传 path + glob），不用 bash grep。**
