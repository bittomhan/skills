# 投标分析：基于具体投标文件的需求对标与满足路径

## 0. 定位与铁律（Tom 08-31 明确）

### 0.1 链路定位——评估报告 vs 投标分析（四点意见第 1 条，永久）

- **"投不投" = 评估报告**（相邻 skill `bid-evaluation-report`）：购标前的初步调研、初判与购标决策；
- **拿到标书之后 = 投标分析**（本 skill）：基于具体投标（招标/采购/磋商）文件的深度分析，产出 `YYMMDD<项目>投标分析.md`。两者边界：评估报告回答"要不要买标/初判"，投标分析回答"需求是什么/差距在哪/条件怎么满足"。

### 0.2 读者区分铁律（四点意见第 2 条，永久）——内部工作语言不进投标分析文档

> 投标分析文档的读者是**决策层（俞总）与团队**，是成品不是工作过程记录。**四类内部工作语言一律不进文档**（发现一条登记一条，清单见 §7）：
> 1. **规则出处标注**："Tom 定 /（08-31 定）/ 永久口径"类字样——文档只陈述结论本身；
> 2. **修正史叙事**："撤销此前判断 / 修正此前判断 / 原待拍板 / 复核后改判"类——直接写当前结论，不写怎么改过来的；
> 3. **内部流程语言**："决策层沟通后回填 §X / 不预设结论 / No-Go / 待拍板"——读者本人就是决策层，改写为面向读者的行动与沟通路径（如"业绩认定口径需与招标人沟通确认，异议窗口至 09-12"）；
> 4. **方法论自我说明**：评估口径说明、"不打分"宣言类段落——核对表本身即体现方法，不必宣告。
>
> **读者视角状态体系（文档内用）**：✅ 已具备 ｜ ⚠️ 有条件具备（写明满足路径与成本）｜ ⏳ 需沟通确认（写明事实＋沟通路径＋时点）。
> **结论节写法**：结论前置，但只写读者关注事项——项目概要 / 对标结果 / 需满足条件 / 已启动的满足动作 / 竞争态势 / 下一步；**不写**判定方法论、文档沿革、内部决议状态、"能力建设定位"类内部校准。
> **skill 与文档的分工**：本 skill（及记忆、经验层）是内部方法论容器，可以出现上述一切内部语言；**只有投给读者的文档受此铁律约束**。

### 0.3 四个核心问题 + 两个补充问题

给出一份投标文件，要回答六个缺一不可：

| # | 问题 | 产出形式 |
|---|---|---|
| 1 | **项目需求是什么**（拆到可执行粒度） | 需求逐条拆解表 |
| 2 | **哪些条目满足、哪些有条件满足、哪些待定** | 满足 / 有条件满足 / 待定 的**逐条**核对表（不打分；不是模块级一句带过） |
| 3 | **能做的如何做到** | 实施路径：自有资源怎么用、外购/合作怎么组织、成本与人力、毛利测算 |
| 4 | **有条件满足的如何补足，补到什么程度后续就能做** | 补强项 + 补齐方式 + 成本周期 + **验收判据**（怎么算补上了） |
| 5 | *（补充）***对手谁会赢、凭什么赢** | 在位者画像 + 我方与对方**能力与经验的定性逐维比较** + 哪些差距可补/不可补 |
| 6 | *（补充）***有哪些歧义必须在投标前钉死** | 提疑 / 澄清问题清单（含通道与时限核查） |

> ⚠️ **常见跑偏**：只做"投 / 不投"的结论，或只把标书内容复述一遍。**判不投不等于分析结束**——不投的标同样要产出"补足清单"，否则这份文件白拿了。

> ⭐ **评估口径铁律（Tom 08-31 定，永久）——条目核对，不打分**：
> 1. 结论**不用"得分差"论证**——条件是定性的不是定量的，按分定能不能做很难。正确做法：对照文件真实条目逐条核对，输出 **"N 条中 X 条已满足，未满足的是哪几条"**，逐条写明具体原因（原文口径 vs 我方事实）；满足的条目不必展开。
> 2. **资质投入也条目化**：依据必须是文件原文条目（资格条款/交付条款/评分项），不自创评分模型；文件里的分值只作权重参考出现，不参与结论推导。关键条目实在不能满足，才判不能投标。
> 3. **竞争对手做定性逐维比较**（我方 vs 对方的能力与经验），不做打分比较。
> 4. **工作方案第一位=投标工作**（已有哪些/缺哪些/如何解决）；找标书、盯守、速判、提疑等方法论产出写进 `科技公司转型/投标经验学习.md`（经验层），不进工作方案。

## 2. 全流程 7 步

### 第 1 步：归档与台账回写
采购文件原件存进项目夹 `招投标简报/01_可参与在途/YYMMDD短名/`，命名 `YYMMDD短名-招标文件（购标原件）.pdf`；同步在台账该条目最后一列写"文件已获取/购标已执行"，避免下轮重复建议。

### 第 2 步：定向提取（不通读全文）
100+ 页文件是常态。先出页号索引，再只读六处：

```python
import fitz, re
txt = "".join(f"\n===== PAGE {i+1} =====\n" + p.get_text() for i, p in enumerate(fitz.open(path)))
pages = re.split(r"===== PAGE (\d+) =====", txt); it = iter(pages[1:])
for n, body in zip(it, it):                      # 只扫章/一级条目的页号，不读正文
    for line in body.split("\n"):
        ls = line.strip()
        if re.match(r"^第[一二三四五六七八九十]+章", ls) or re.match(r"^[一二三四五六七八九十]、", ls):
            print(f"p{n} | {ls[:50]}")
```

| 位置 | 拿什么 | 服务于第几问 |
|---|---|---|
| 第三章 评标办法前附表 | 分值构成、商务/技术每小项分值与评审标准、基准价公式 | 评估（②） |
| 第五章 技术标准和要求 | 建设内容分层、接口清单、算法/数据/安全条款、团队与工期门槛 | 需求拆解（①） |
| 第五章 限价明细 + 附件设备清单 | 软件模块限价、硬件逐项单价数量、合规件单价 | 实施路径（③） |
| 第四章 合同主要条款及附件 | 工期、质保、驻场、付款节点、违约金、知识产权、验收权、安全/保密协议 | 评估（②）+ 补足（④） |
| 第二章 投标人须知前附表 | 资格条件、联合体/分包、偏离、**疑问与异议的提出方式/截止时间**、踏勘与预备会安排、保证金、暗标、CA | 评估（②）+ 提疑（⑥） |
| 第六章 投标文件格式 | 需提交的材料清单、分项报价格式、承诺函模板 | 实施路径（③） |

### 第 3 步：需求逐条拆解（第①问）
**粒度要求**：拆到"可独立判定能否交付"的条目，不是抄章节目录。智能化类标按「业务应用 → 功能模块 → 关键要求（参数/接口/算法/指标）」三层拆；服务类标按「服务内容 → 频次/人数/时长 → 交付物与验收标准」拆。每条标注：[原文级] 或 [推断] + 置信度。

### 第 4 步：竞争态势与在位者画像（补充·第⑤问）

> **为什么必须做**：只评估"我方缺什么"会得出误导性结论——**能不能赢取决于相对位置，不取决于绝对能力**。同一份能力清单，在没有在位者的标里够用，在有在位者的标里不够用。**竞争对手情况是当前应重点调研实现的事项，不是可选装饰。**

**查什么（四个来源，按优先级）**

| 来源 | 查法 | 拿到什么 |
|---|---|---|
| 采购人历史招标 | 同一采购人在本平台/公共资源交易平台的历年中标公告 | 在位者名单、历史成交价、是否被同一家连续拿下 |
| 公开商业数据库 | 企查查/天眼查/爱企查查中标记录（按竞对名称反查） | 竞对的主战场、单笔规模、客户结构 |
| 同类标的开标数据 | 同赛道其他项目已公开的开标数据表（如中储粮系统开标记录） | 玩家图谱与价格带 |
| **评分表反推** | 从"类似业绩"的口径与分值倒推甲方想要什么样的供应商 | 甲方心中的在位者画像（这往往比外部检索更准） |

**画像表字段**：竞对名称 ｜ 与本项目采购人的历史合作（项目/金额/年份）｜ 近期同类战绩 ｜ 优势（业绩/本地化/系统对接/供应链）｜ 置信度。

**比较方式：定性逐维比较（不打分）**——建"维度 × 我方 × 对方 × 差距性质"表。维度示例：行业业绩类型 / 系统对接经验 / 交付团队 / 现场经验 / 合规能力 / 本地化 / 价格。每维标注差距性质三选一：**可补（写如何补）/ 结构差距（由主业决定，短期不可补）/ 我方强项**。

**必答两问**：①谁最可能赢、凭什么赢；②我方与对方的差距条目哪些可补、哪些不可补（不可补的写明根因）。

**落位**：竞对档案存 `招投标简报/竞争情报/`；开标结果（中标人、中标价、软硬件拆分）公示后回填至基准库对应样本的 S<n>-7 节。

### 第 5 步：条目逐条核对（第②问）
每条需求按**条目核对口径**判定，并写清依据（**不打分、不列分值推导**）：

| 判定 | 含义 | 写法要求 |
|---|---|---|
| ✅ **满足** | 现有能力可直接交付 | 写明用哪几项既有能力（软著/经验/网点/资质），最好是可被评审采信的证据 |
| ⚠️ **有条件满足** | 需外购、合作、招聘或二开后能做 | 写明缺的那一块 + 补上后即可做（人力可随项目招聘/属地雇佣/劳务外包扩编——**不得机械以注册员工数判定不可满足**；禁止分包=履约合规义务，自行履约即满足） |
| ⏸ **待定（不预设结论）** | 事实与口径不符、但处理方式需决策层定 | 写明事实（如业绩口径 vs 我方合同类型）+ 标注"提交决策层沟通后回填"；不写❌不否决 |

> 每标例行默认满足条目：纳税信用等级（A 级证明由财务出具）。

**不要只做模块级判断**（如"软件平台做不了"）——要落到条目（如"告警联动引擎做不了、但巡检任务调度能做"），否则无法指导补足。

### 第 6 步：能做的如何做到（第③问）
对每个 ✅/⚠️ 项给出实施路径：自有资源怎么用 / 外购或合作方怎么组织 / 成本与人力估算 / 关键里程碑。**必须算经济性**：外购成本 + 自有成本 vs 该模块限价 → 毛利空间。若算下来不赚钱，即使"能做"也要标注为"能做但不建议做"。

### 第 7 步：有条件项如何补足（第④问）
每个 ⚠️/⏸ 项中需要建设的部分映射为一条补强项，写入能力层清单 A 表，字段固定：

`缺口 ｜ 层级(L0-L5/全局) ｜ 为什么缺/影响 ｜ 补齐方式（自研/外购/合作/考证/放弃）｜ 成本与周期 ｜ 验收判据（补到什么算够）｜ 优先级 ｜ 状态`

**验收判据是本节最容易漏、也最关键的一栏**——没有判据就无法判断"补上了没有"，后续标的仍会重复分析。判据要可检查（"完成 1 个试点 + 形成作业指导书""取得证书并可在目标标型中计分""中间件在 1 个项目中复用"）。

### 第 8 步：提疑 / 澄清问题清单（补充·第⑥问）

> **双重价值**：①降低投标风险（把歧义钉死在投标前，避免中标后被验收口径反噬）；②**合法接触采购人**——答复通常面向所有投标人公开，是获取补充信息的正规途径（对我们这类想切入的新供应商尤其重要）。

**先查清楚有没有提疑通道**（三种情形，逐个确认）：

| 情形 | 依据条款 | 时限 |
|---|---|---|
| 投标预备会（提问+集中澄清） | 前附表 1.10.1-1.10.3 | 前附表载明的"提出问题截止时间" |
| 常规答疑 | 前附表/正文 2.2 条 | 常见口径：**投标截止 15 日前**招标人发出澄清 |
| 对招标文件的**异议** | 正文 2.4 条 | 常见口径：**投标截止 10 日前**提出，招标人 3 日内答复，答复前暂停招标投标活动 |

> ⚠️ 许多项目前附表里"投标预备会=不召开""提出问题截止时间=／"，这不代表没有提疑通道——**必须再查正文 2.4 异议条款**（黄金叶即属此情形：预备会不召开，但异议窗口 = 截止前 10 日 ≈ 09-12）。

**问题清单的标准七类**（从每份文件里逐类过，找出真实歧义，不要凑数）：

1. **范围歧义**：工程量/数量未明确的项（如"仅针对已安装 XX 的烟箱"但未给出数量）；
2. **验收口径**：指标未量化、无法据以承诺的项（如要求"算法适配"但未给识别准确率/误报率门槛）；
3. **责任划分**：接口对接失败、硬件更换、测评费用、翻垛/安装配合由谁承担；
4. **人员口径**：驻场人数是否含项目经理、覆盖周期、是否需特定资质；
5. **费用归属**：等保测评费、第三方检测费、驻场交通食宿、培训费是否已含在限价内；
6. **评分口径**：业绩认定范围（如"仓储或养护类"是否含监管服务合同）、证书是否需特定颁发机构；
7. **交付边界**：预留接口/后续扩展是否属本次范围、质保期起算与终止条件。

**纪律（三条）**：①问题表述**中性专业**，不暴露我方短板（如不问"我没有业绩，X 行不行"，而问"X 类合同的认定口径是什么"）；②不借提疑谈商务；③**若已判定 No-Go，不要以纯情报目的提起异议**——异议程序有"利害关系人"身份基础，滥用有声誉风险；此时只把清单与窗口时点记录下来，供后续真正要投的标的复用。

### 第 9 步：收尾三同步
1. 台账该条目更新（结论 + 新增补强项 + 待拍板事项）；
2. `.workbuddy/memory/YYYY-MM-DD.md` 追加：归档位置、改变判断的发现、新增/修订的补强项、在位者情报、新赛道信号；
3. 产生跨标的、跨周期结论时，升级写入 `.workbuddy/memory/MEMORY.md`。

> **开标后回填动作**：中标结果公示后，把中标人、中标价、软硬件拆分（若公示）回填基准库 S<n>-7，并更新竞对档案——这是把"一次性分析"变成"可累积资产"的关键一步，不要漏。

## 3. 内容质量九问（写完逐条自检）

1. **有没有拆到条目级？** 只做模块级判断 = 不及格。
2. **每条评估有没有依据？** 依据要写"用哪几项既有能力"或"缺哪一块"，不能写"经验不足"。
3. **能做的有没有算经济性？** 能做 ≠ 值得做。
4. **有条件满足的有没有落到补强清单并有验收判据？** 只写"需要补齐"= 没做。
5. **所有数字有没有来源与置信度？** [高]=原文 [中]=推断 [低]=单源未核实。
6. **结论是否前置？是否条目化？** 第一节是结论；论证用"X/Y 条满足+未满足条目明细"，不出现"差 X 分"类打分推导。
7. **有没有做在位者画像并做定性逐维比较？** 没有对照系的"不能做"结论是不可信的；比较维度要标注"可补/结构差距/我方强项"。
8. **有没有提疑清单，且通道与时限核查过了？** 前附表写"／"不等于没有通道。
9. **有没有内部工作语言残留？（读者区分铁律 §0.2）** 逐条扫四类：规则出处标注 / 修正史叙事 / 内部流程语言 / 方法论自我说明——任何一类出现在给读者的文档里都打回重写。

## 4. 反模式清单

| 反模式 | 正确做法 |
|---|---|
| 通读 9 万字全文再动笔 | 先出页号索引，定向读六处 |

| 只给"投/不投"结论，不拆能做不能做 | 四问全答；不投也要产出补足清单 |
| **用"得分差 X 分"论证能不能投** | 条目核对："N 条中 X 条满足，未满足的是哪几条"+逐条原因（08-31 Tom 定） |
| **用自创评分模型/权重打分** | 只用文件原文条目；文件分值仅作权重参考，不参与结论推导 |
| **对手比较做成打分对比** | 定性逐维比较，每维标"可补/结构差距/我方强项" |
| 用"占比较高""要求严格"等含糊词 | 条件尽量数字化（人数/天数/金额/占比），但结论推导用条目不用分数 |
| 缺"验收判据"栏 | 每条补强项必须写清"补到什么算够" |
| 把补强清单复制到样本文档 | 样本文档只写新增/修订项并指向能力层 |
| 把找标书/盯守/速判/提疑方法论写进工作方案 | 方法论进 `科技公司转型/投标经验学习.md`；工作方案只写本项目评估与能力盘点 |
| 新样本自创字段 | 数据层严格套用 S<n>-1~7 模板，否则无法横向比对 |
| 购了标就把初判结论机械翻成 Go | 先条目核对；⚠️/⏸ 条目写明可满足路径（招聘/外购/提疑沟通），不可补的根因写清，结论交决策层定 |

## 5. 速判表（逐条核查，非硬否决——08-31 九点修正后口径）

**速判阶段不存在"任一命中即放弃"的自动否决条目**。下列条目命中时转入逐条核对与专项测算，结论提交决策层定：

| # | 条目 | 命中后动作 |
|---|---|---|
| C1 | 业绩口径为"软件开发/软硬件集成实施"且分值高 | ⏸ 不下结论：认定口径可提疑/沟通争取，处理由决策层定 |
| C2 | 驻场人数多 / 工期长 | 人力专项测算（岗位/人数/周期/招聘来源/成本计入报价）——人力可随项目扩编 |
| C3 | 不允许联合体 且 不得分包 | 自行履约即满足（履约合规义务）；仅减少一个资源组织选项 |
| C4 | 硬件占比高 | 测算议价能力与供应链方案后定，不预设否决 |
| C5 | T3 区外且当地无网点 | 测算属地雇佣/本地合作方案后定 |

**默认满足条目（每标例行核对一次）**：纳税信用等级（A 级证明由财务出具）。

**方向性筛选（提示评估顺序，不作结论）**：服务段/软件占比高的标能力结构更匹配；业绩口径为监管/仓储服务类时我方有直接对应；金额小、驻场少的标人力组织成本低；服务类标金额可放宽；T1/T2 半径内或有本地合作方的标交付成本低。

**速判顺序**：评标办法前附表（业绩口径）→ 技术标准章项目要求（驻场/工期）→ 限价明细表（软硬件占比）→ 公告资格要求（联合体/分包/地点）。

> **已知方向性结论（08-31，复用前先确认是否仍成立）**：IT 总包/智能化建设类标的的评分条目本质是「软件开发业绩 × 驻场团队」——业绩类型由主业决定（认定口径可提疑/沟通争取）、交付团队可随项目组建招聘，两者均按条目核对处理、**不作绝对化否决**；证书类条目可购买。→ **Tier 1/Tier 2 资质投入的正确战场仍是服务类标（银行押品入围 / 政府司法保管 / 储备物资核查）；证书考试同理，先确认目标标型再考。**
