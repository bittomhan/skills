# 更新进度 SVG（牌照递交时间线与材料就绪情况）

## 用途
生成/更新 `Gemtrust/Gemtrust｜牌照递交时间线与材料就绪情况.svg`——**给公司团队**的牌照进度可视化。注意受众分工：**SVG=给团队说明，`进度记录说明.md`=给俞总的完整说明**。

## 触发
- 「生成进度 SVG / 更新进度图 / 画时间线图 / 更新进度 SVG」
- 任何需要给团队的牌照/材料进度可视化。

## 设计规范（Tom 2026-08-19 定，不可回退）
1. **两条等长对齐的时间轴**：CMS（Capital）一条、MPI（Stable）一条，**刻度对齐、等长**（都从「现在」到「发牌」，虚线参考线对齐）。
   - CMS 递交里程碑 = 9中–10初；MPI 递交里程碑 = 10–11月（MPI 递交点在 CMS 右侧，反映时间先后）。
   - **轴区分度**：CMS 轴 = 蓝 `#185FA5`、MPI 轴 = 红 `#B42318`（递交前主段 + 「现在」「递交」里程碑点 + 阶段②标签，都用各自线色）。
   - 每条轴按阶段分段着色：阶段② 递交前=各自线色（蓝/红）、阶段③ 审核期=灰 `#9CA3AF`、阶段④ 持牌后=浅灰 `#D1D5DB`；阶段标签直接标在轴上。
2. **材料分线分阶段**：CMS 材料挂在 CMS 轴下、MPI 材料挂在 MPI 轴下，各按「递交前 / 审核期 / 持牌后」分组。
3. **共用材料沉底单独展示**：不放进 CMS 或 MPI；在图片最下方单独一块「共用材料（两牌照都要）」，同样按阶段分（递交前 / 审核期）。
4. **状态点**：绿 `#16A34A`=具备、黄 `#D97706`=进行中/初稿已成、灰 `#9CA3AF`=未开始。
5. **不展示花钱金额**：花钱（金额/政策依据）只放 `进度记录说明.md` 第三节；SVG 只展示「要交什么 + 是否具备」，**图底部不放任何说明句**（状态色图例已在顶部）。
6. **字体/样式**：Noto Sans CJK SC（回退 PingFang SC / Microsoft YaHei）、浅底深字、中文字面、`viewBox="0 0 680 <高度按内容>"`。

## 工作顺序（重要）
1. **先读** `进度记录说明.md` 第二节（各阶段详细提交材料说明）——它是内容唯一来源。
2. 再读两份清单置顶看板取状态（🟢→绿 / 🟡→黄 / ⬜→灰）：
   - `Gemtrust/CMS_Capital/Gemtrust Capital｜CMS牌照申请材料清单.md`
   - `Gemtrust/MPI_Stable/MPI稳定币牌照申请材料清单.md`
3. 按上述规范生成 SVG，覆盖写入 `Gemtrust/Gemtrust｜牌照递交时间线与材料就绪情况.svg`。
4. `present_files` 呈现；如要发微信/团队，用 md-to-pdf 转 PDF（嵌入 Noto Sans CJK SC）。

## 关键要点（本次沉淀）
- 图中材料必须能在 `进度记录说明.md` 第二节找到对应说明；图是文档的浓缩，不能自造材料。
- 缺口集中在 MPI 线：EA 报告（灰）、交易流程图（灰）；共用侧政策包（灰，DIY 可补）。
- 花钱不画进 SVG。
