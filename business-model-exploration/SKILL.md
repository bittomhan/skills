# 商业模式探索（对标先行 → 验证 → 决策）

## 定位

把一个模糊方向变成「已验证的商业模式」。不从零发明模式——先调研已成功的同类案例（对标），选模式，再在自己的资源语境下验证。探索产出恒为资产（模式卡/检索库/方法论），不依赖任何单一合作方。

执行前先读 `references/workflow.md`（七阶段完整细则 + 牙植士实战首例要点），输出物按 `references/templates.md` 的模板生成。

## 执行流程（七阶段）

**阶段 0 · 启动定位**：写三行探索章程——①性质（探索学习型=默认 / 顾问交付型=对方付费委托）②预算上限（时间/检索额度/精力，可承受损失原则）③资产沉淀目标（这次探索无论结局沉淀什么）。意愿监测贯穿全程（四个领先指标见 workflow.md），触发处置=冻结执行层，探索继续。

**阶段 1 · 对标先行**：成功案例普查（Consensus Deep Research 问跨国模式 + 媒体源补本地先例）→ 逐案六要素拆解（需求引擎/供给结构/获客信任/单位经济/天花板/前提条件）→ 提炼共性要素清单 + 前提条件矩阵 → 适配筛选（对照用户资源打三档：已有/可组装/硬缺；硬缺=一票否决或重设计）→ 产出**模式卡**（模板见 templates.md）。失败案例同步入单，提炼「模式的死法」作红线。

**阶段 2 · 骨架方案**：以模式卡为地基，0.5-1 天，结论先行，做到「够质疑者用」即可。执行层文档（价目/话术/模板/分工）此阶段一律不做——它们是验证结论的下游产物。

**阶段 3 · 质疑驱动验证**：找最强质疑者（找不到用 AI 红队或目标客户访谈替代）→ 质疑拆成可检验命题（不辩护不反驳，质疑成立的直接吸收）→ 量化框架先行（核心算式 + 硬门槛，如回本倍数 <2× 不投）→ 分层检索设计（P0/P1/P2；每问两注「喂给哪个决策 + 好答案的样子」；学术库覆盖弱的问题事前分流走网络源；额度留 ≥1/3 给追问）→ **门槛表先定再采数据** → 检索执行与全量存档 → 综合分析（命题终判 + 修订指令汇总）→ 二次审视 → 验证简报（按读者心理定制结构，抵触读者=还账表+砍单记录+默认通过制）。

**阶段 4 · 决策（两个独立判断分开裁决）**：①模式是否成立——按预定门槛表裁决；②执行投入是否启动——意愿信号未触发冻结 + 资源到位。**模式成立但执行条件不足 = 探索完成入库，不算失败**——检索库/模式卡/方法论归档，等下一个有意向的合作方直接调用。

**阶段 5 · 执行层展开**：执行条件满足后才做——按修订指令直接写 v2（跳过 v1 返工）；交付包 PDF 此 时才生成。

**阶段 6 · 复盘沉淀**：死因归档（写进项目 README）+ 资产归档（检索库按主题标可复用性、模式卡入库）+ 方法论回写 workflow.md。

## 关键纪律

1. **检索主力 = Consensus Deep Research**（一次一问，出带引用合成报告，用户不自己找文献）；Undermind 可选补漏；商业数据（价格/佣金/转化/本地画像）学术库覆盖弱是常态——检索设计阶段就分流到官网/行业报道/直接问询，不反复换问法重跑。**初期信息整理按 workflow.md「Consensus 调研角度指南」执行**：七类问题角度模板（全景/普查/机制/痛点/参数/风险/空白）+ 未知角度拓展四法（问综述的综述/主题盘点/反向问失败/相邻迁移——解决 unknown unknowns，让文献替用户扩展问题清单、提前掌握方向）+ 六条整理纪律（引用必存/意外发现登记追问/命中薄标注/共识度检查/数字钉死/机制与流量证据分账）。
2. **先调研再生成**：对标先于方案、门槛先于数据、执行层后于验证。
3. 事实必标出处 + 可信度分级（高=官方/同行评审 ＞ 中=行业调查 ＞ 低=自媒体/单源）；关键官方数字三源交叉；诚实区分「文献证实的是打法，证实不了的是市场」。
4. 探索者默认：**不为合作方意愿推迟探索，只为意愿未确认推迟执行层投入**。有成功经验后谈判地位靠成果换，不靠先谈判。
5. 与 dbs-benchmark 分层：方向未定先跑 dbs-benchmark（方向层对标，排除「我」的噪音）；方向定了进本流程（模式层对标）。
6. 输出项目文件夹结构与命名按 templates.md 末节执行；检索原始结果全量存档（没有来源的数字无法标可信度，无法进论证）。
